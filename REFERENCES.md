- [Depth Anything V2 official metric-depth instructions](https://github.com/DepthAnything/Depth-Anything-V2/blob/main/metric_depth/README.md): outdoor VKITTI small checkpoint and fixed `max_depth=80 m` setting.
- [Depth Anything V2 metric source](https://github.com/DepthAnything/Depth-Anything-V2/tree/a561b849ebae10a6f5ef49e26c83cbbcd36c71bf/metric_depth/depth_anything_v2): exact vendored inference architecture revision. Upstream source and the selected model card are Apache-2.0 licensed; the vendored package includes the upstream license and retains DINOv2/Meta notices.
- [Official Metric VKITTI Small model card](https://huggingface.co/depth-anything/Depth-Anything-V2-Metric-VKITTI-Small) and [checkpoint file page](https://huggingface.co/depth-anything/Depth-Anything-V2-Metric-VKITTI-Small/blob/main/depth_anything_v2_metric_vkitti_vits.pth): official 99,221,808-byte state dictionary, with independently published SHA-256 `9203e538d35255c90dda4b7fedb47ff33fe725497bcca3b1e53b3a65ee63f0cb`. The project verified its downloaded file against this digest; that does not validate metric accuracy on real roads.
- [Virtual KITTI 2 dataset format and terms](https://europe.naverlabs.com/proxy-virtual-worlds-vkitti-2/): depth PNG intensity is centimeters to the **camera plane**, and the official [metric training loader](https://github.com/DepthAnything/Depth-Anything-V2/blob/a561b849ebae10a6f5ef49e26c83cbbcd36c71bf/metric_depth/dataset/vkitti2.py) divides by 100 to obtain meters. This supports approximate camera-axis Z semantics. VKITTI 2 dataset terms are non-commercial CC BY-NC-SA 3.0, distinct from the code/model Apache license.
- [KITTI object benchmark](https://www.cvlibs.net/datasets/kitti/eval_object.php): annotated 2D/3D object data and evaluation context. Its **labeled training data**, split into train/validation for this research, is required to compare against 3D object locations; hidden test annotations cannot be used locally for this analysis.
- [KITTI development kit / data format](https://www.cvlibs.net/datasets/kitti/eval_object.php?obj_benchmark=3d): consult the calibration and label format when implementing evaluation; `location` is a camera-frame box reference and differs from a visible-surface point.

## Milestone 5 KITTI source, access and interpretation

- [Official KITTI 3D object benchmark and development-kit downloads](https://www.cvlibs.net/datasets/kitti/eval_object.php?obj_benchmark=3d): the labeled object **training** partition supplies 7,481 images and 3D labels. Its left-color image archive is approximately 12 GB, camera-calibration archive approximately 16 MB, training-label archive approximately 5 MB, and development kit approximately 1 MB. Use `image_2`, `label_2`, `calib` and the official devkit's format documentation. The unlabeled test partition is unsuitable for local reference-Z scoring. The user supplied local ZIPs consistent with these official structures; the project did not download them. Archive filenames alone do not independently authenticate their publisher.
- [Official KITTI registration page](https://www.cvlibs.net/datasets/kitti/user_register.php): official download access requests an account with institutional email and stated research purpose. Respect that process; no mirror should bypass it.
- [Official KITTI dataset home and license](https://www.cvlibs.net/datasets/kitti/): KITTI data are provided under Creative Commons Attribution-NonCommercial-ShareAlike 3.0. The source-drive identity of each object benchmark frame is not established by the selected archive IDs, so a hashed frame split does not guarantee independent drives.
- The supplied official development kit's `readme.txt` documents KITTI object's 15-field label record: category, truncation, occlusion, observation angle, 2D box, `(h,w,l)`, camera-coordinate `(x,y,z)`, and Y rotation. Its `matlab/computeBox3D.m` sets lower box corners at local `y=0` and upper corners at `y=-h` before adding `location`, confirming the bottom-center 3D-box reference convention. Depth Anything's image depth is a predicted visible-surface quantity; M5 compares it with `location_z` only as an explicitly named **object-reference Z proxy**. The devkit documents projection to left color as `P2 * R0_rect * Tr_velo_to_cam`; `P2` is 3×4 and may carry translation. Optional sparse LiDAR surface diagnostics require this full chain and point-to-object association.

## Milestone 3 road and lane segmentation

- [TwinLiteNetPlus official source](https://github.com/chequanghuy/TwinLiteNetPlus/tree/90f1b8695ae311d5123b05f8534b2e11e42499d2): upstream revision used for the vendored Small model and configuration. The upstream repository's [MIT license](https://github.com/chequanghuy/TwinLiteNetPlus/blob/90f1b8695ae311d5123b05f8534b2e11e42499d2/LICENSE) is retained with the inference source.
- [TwinLiteNet+ paper](https://arxiv.org/abs/2403.16958): describes the separate drivable-area and lane segmentation tasks and the Small model's 0.12M-parameter, 1.40 GFLOP configuration on BDD100K. These published dataset results are not this project's bus-image accuracy.
- [Authors' pretrained checkpoint folder](https://drive.google.com/drive/folders/1EqBzUw0b17aEumZmWYrGZmbx_XJqU-vz): contains `small.pth` (Google Drive file ID `1N7jNsa8P1dM-UevqPRsx6heUpN4L00FJ`). The 594,777-byte file's SHA-256 was computed locally as `0dd3bd7356a5b70e1d21ae60cd09b55641b48bde738393177f94daff17ab6360`; no independent publisher digest or separate checkpoint license was located. The repository states an MIT source license; redistribution terms for weights are not separately stated.
- [Upstream demo and training loader](https://github.com/chequanghuy/TwinLiteNetPlus/tree/90f1b8695ae311d5123b05f8534b2e11e42499d2): `demo.py`, `demoDataset.py`, `BDD100K.py`, and `model/model.py` establish RGB `/255` input, 384×640 training letterbox, two 2-channel outputs, binary foreground targets, and argmax-based postprocessing. This project's adapter restores both channels after exact padding removal and uses original-frame masks.
