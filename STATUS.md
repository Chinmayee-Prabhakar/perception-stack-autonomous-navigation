## M2 — Metric monocular depth

Implemented and committed as M2 milestone. The official Depth Anything V2 Metric VKITTI Small checkpoint produces original-resolution `float32` camera-axis Z estimates in meters and a boolean validity mask. Its 99,221,808-byte checkpoint matches the independently published SHA-256 `9203e538d35255c90dda4b7fedb47ff33fe725497bcca3b1e53b3a65ee63f0cb`; strict metric `vits` loading succeeds.

The CPU bus-image demo produces an 810×1080 array with 874,800 finite positive values. Predicted min/median/mean/max are 5.553/12.477/14.219/33.389 m, with no values within 1% of the model's nominal 80 m cap. These are visible-surface predictions on an unlabeled photo, not KITTI accuracy or 3D object-reference locations. Synthetic-to-real depth accuracy remains unmeasured.

## M5 — KITTI object-reference Z proxy evaluation

The evaluation infrastructure and primary real-data study are complete, independently reviewed, and accepted for local version control. The loader validated 7,481 label/calibration pairs from user-supplied local KITTI object archives; no dataset download occurred. The full `P2` matrix, including nonzero translation terms, is retained. A conservative Car/Pedestrian mapping, frozen pilot/development/held-out IDs, one-to-one 2D matching, M4 estimator reuse, paired proxy metrics, CPU CLI, and plots/reports are implemented. The metric-depth checkpoint, scale policy and all thresholds stayed fixed; no KITTI label was used to fit depth scale or select a sampling method. The selected IDs and source fingerprint are preserved in `configs/kitti_split_manifest_v1.json`.

The **pilot** processed 16/16 frames: 52 eligible references, 38 matches, and 38 valid pairs. Its box/mask mean absolute **object-reference Z proxy** errors were 4.538/4.375 m. The **held-out** study processed 256/256 distinct frames: 1,157 eligible references, 785 matches, 372 unmatched references, and 785 valid pairs. Box/mask mean absolute proxy errors were **3.703/3.837 m**; median absolute errors **2.416/2.519 m**; signed mean biases **+3.140/+3.361 m**. Mean paired mask-minus-box absolute proxy error was **+0.134 m** (frame-bootstrap 95% interval **[+0.060,+0.215] m**, 240 contributing frames, seed 549, 1,000 replicates). Mask error was lower for 53.9% of paired objects, but larger mask-worse cases raised its mean. Pilot and held-out findings are reported separately; the pilot is not evidence of a general mask advantage. Frame grouping may not equal drive grouping, so the interval does not capture possible same-drive correlation. These are **annotated bottom-center reference-Z proxy** errors, not visible-surface depth or full 3D localization accuracy.

The independent visible-surface diagnostic remains pending suitable approved aligned depth/LiDAR data and a correspondence policy. M3 representative landscape-road validation remains pending. **30 M5 offline tests passed**; the M5 full fast suite reported **89 passed, 3 skipped**, and the separate opt-in depth/road/fusion integration suite reported **3 passed**. ## M6 — Image-space road adjacency and scene visualization

The fixed contact policy samples central pavement immediately **below** each box, using 60% of box width and a band of max(2 pixels, 15% of box height). Pixel membership is integer-center, half-open and clipped. A region needs six pixels and at least half of its ideal area; predicted drivable overlap ≥0.50 yields `drivable_adjacency_detected`. Other valid regions yield `drivable_adjacency_not_detected`. Boxes touching image edges now yield `unknown_image_boundary` rather than a definitive result or an assertion of truncation. Explicit annotation hints distinguish `unknown_truncated` and `unknown_occluded`; insufficient coverage, missing road and invalid regions remain separately unknown. These are image-space evidence statuses, not occupancy probabilities or safety labels. Lane pixels are kept separate.

The typed scene joins unchanged M4 depth estimates, road evidence, model/checkpoint provenance and explicit calibration/visualization statuses. The camera overlay and strict JSON are generated on original pixels. A metric camera X–Z plot is produced only with verified rectified intrinsics and valid M4 selected-ray surface points. The bus image has no such calibration, so no 3D coordinates or metric X–Z output are produced. The separate synthetic fixture verifies X–Z points (−5,10) and (+10,20) m and equal metric axes.

The independent review reproduced a scene-consistency defect: associations computed from a positive road mask were accepted beside a same-identity all-zero replacement mask. Scene assembly now verifies deterministic source fingerprints covering detector identities/boxes, policy, both full-resolution road/lane mask contents and road provenance, then recomputes contact diagnostics using preserved visibility hints. Rendering validates the same pairing before drawing. The fingerprints enforce local data consistency, not model authenticity or accuracy. `matplotlib` is now a direct project dependency, compatible with the existing pinned Windows lockfile; the environment was not reinstalled.

A subsequent adversarial review found that an original M4 fusion result could be paired with detections whose instance mask pixels had changed or whose mask had disappeared, even when road associations were recomputed. Failing synthetic regressions reproduced both cases. M4 fusion now records a versioned SHA-256 detector-input fingerprint of frame/detector identity, ordered class/confidence/box metadata, and mask presence, shape and exact pixels. Scene assembly checks it against the supplied detections; overlay rendering inherits that check. The road-association fingerprint remains box-only because its computation does not use instance masks. Legacy M4 results without this fingerprint remain valid standalone results but cannot be assembled into a new scene until fusion is rerun on the supplied detections. These hashes verify local pairing, not model authenticity or depth accuracy.

The corrected CPU bus run processed an **810×1080** image: six detections, six valid box depths, six valid mask depths, 147,229 predicted drivable pixels and 18,456 predicted lane pixels. Association statuses are **two detected, three not detected, one unknown**, compared with **two/four/zero** before boundary correction. Detection #5 touches the left image boundary (`x1=0`), so its prior negative status is now `unknown_image_boundary` even though its sampled foreground fraction remains zero. The overlay uses `adj+`, `adj-`, `adj?` with an explicit predicted-adjacency legend. The bus output remains qualitative and visibly retains M3's top/bottom lane artifacts. The final source-consistency suite reports **136 passed, 3 skipped**; the separate opt-in depth/road/fusion tests report **3 passed**. The new bus scene JSON differs from the prior corrected output only by fusion-source provenance; its overlay and association JSON remain byte-identical. The synthetic X–Z points remain (−5,10) and (+10,20) m. M5's frozen source/configuration has no diff, and all 309 M5 review-output files remain byte-identical to their local originals. The 256-frame/785-pair object-reference Z proxy result is unchanged. Representative marked-road validation, a real verified calibrated plot, and the separate LiDAR visible-surface diagnostic remain pending. Optional Blender work is still later. The final M6 implementation is accepted for local version control; no remote is configured and nothing was pushed. **M5-L** is the proposed next scientific extension and has not begun.
