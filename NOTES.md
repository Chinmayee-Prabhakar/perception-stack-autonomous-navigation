## M3 — Preprocessing and alignment audit

- Upstream training/validation reads BGR with OpenCV, then converts to RGB CHW and divides by 255. Its image path letterboxes to **384×640** with `INTER_LINEAR` and RGB-equivalent 114 padding. The separate training label path resizes annotations to **640×360**; the training loss crops 12 top and bottom rows from output for BDD landscape images. That label convention is not an inference transform for arbitrary input aspect ratios.
- Upstream demo uses a 640-square nominal input with stride-adjusted automatic padding and restores using an integer inverse ratio. The adapter deliberately uses the training image resolution, exact recorded top/bottom/left/right padding, and an explicit target size for original-frame restoration. This avoids assuming a fixed 12-row crop or an integer inverse scale for portrait and odd-sized images.
- Both heads have channel 0 background and channel 1 positive semantic pixels. The loader thresholds each grayscale annotation at >1 to create binary targets. The adapter removes padding from both full-resolution score maps, bilinearly restores both channels with `align_corners=False`, then argmaxes; no sigmoid or arbitrary threshold is used. `FrameRoadSegmentation` owns separate original-resolution boolean masks. Drivable area is not all road surface, and the lane mask is not a fitted boundary, centerline, or trajectory.
- Deterministic tests exercise wide landscape, tall portrait, square, odd dimensions, asymmetric padding, RGB channel order, padding-only false positives, spatial corner markers, model-output shape, and input immutability. No adapter correctness defect was found in this audit; the new tests strengthen alignment coverage.

## M4 — Sampling, geometry, and regression evidence

- M4 began from a clean M3 commit M3 milestone; M2 and P0/P1 history are preserved. No remote exists and nothing was pushed.
- Both methods operate on the same original-resolution frame, detections, and depth. Box membership is based on integer pixel centers in clipped float `[x1,x2)×[y1,y2)`; mask membership is the instance mask intersected with that box. The shared valid mask means finite positive camera-axis Z. Defaults are at least 3 valid pixels and at least 10% valid fraction. Median is the representative region Z; mean/min/max, population standard deviation, IQR, MAD, counts, fraction and >=99%-of-nominal-80-m near-cap fraction remain diagnostics. A failed threshold is marked unavailable even when diagnostic values exist. No invalid depth is replaced with zero and no per-test-label tuning is used.
- Each method chooses an actual valid pixel by minimum absolute difference to its region median, then minimum squared distance to the centroid of *all region pixels*, then smaller row `v`, then smaller column `u`. This same policy is used for box and mask. The pixel's own Z can differ from median Z. Selected-ray backprojection uses only that actual Z. Missing, empty, sparse, clipped-away, invalid, and no-depth cases have explicit status/reason; overlapping detections are sampled independently.
- The rectified pinhole implementation uses `X=(u-cx)Z/fx`, `Y=(v-cy)Z/fy`, `Z` forward, and separately computes Euclidean radial range. It requires finite positive focal lengths, finite principal point, matching image dimensions, explicit rectification, and calibration provenance. Synthetic backprojection tests pass; real calibrated backprojection remains undemonstrated. A raw `P2` calibration file is rejected rather than dropping its translation terms. The bus photo has no verified intrinsics, so all metric 3D coordinates are unavailable. Surface points, when available, are *estimated visible scene points*, not KITTI object-reference locations.
- Baseline fast suite: 45 passed, 2 skipped. After M4: **59 passed, 3 skipped**. The opt-in real depth, road and fusion checkpoint suite: **3 passed**. Detector CLI regression: six bus-image detections. The CPU fusion CLI produced six detections, six valid box medians and six valid mask medians; JSON and overlay were generated. Its median pairs `(box, mask)` in meters by detector order are: bus `(12.73, 13.01)`, person `(13.06, 9.25)`, person `(10.18, 9.65)`, person `(10.69, 10.23)`, stop sign `(16.52, 16.34)`, person `(9.78, 9.38)`. These are unlabeled predictions, not accuracy scores. Full per-object counts and provenance are in `outputs/bus_fusion.json`.
- Remaining limitations: VKITTI synthetic-to-real shift, possible occlusion/background contamination, incomplete or noisy instance masks, sparse small objects, near-80-m saturation, no calibrated monocular uncertainty, no KITTI quantitative evaluation, and lack of verified bus calibration. Future KITTI comparisons must freeze class mapping, one-to-one matching, split, calibration, and reference-point semantics before measuring accuracy. M3's top/bottom lane false positives remain; upstream loss excludes the first/last 12 model rows from direct training supervision, a plausible but unproved reliability factor. Representative landscape-road validation remains pending by choice. Blender is optional after core quantitative evaluation.
