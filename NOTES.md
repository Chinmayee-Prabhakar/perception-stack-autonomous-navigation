## M3 — Preprocessing and alignment audit

- Upstream training/validation reads BGR with OpenCV, then converts to RGB CHW and divides by 255. Its image path letterboxes to **384×640** with `INTER_LINEAR` and RGB-equivalent 114 padding. The separate training label path resizes annotations to **640×360**; the training loss crops 12 top and bottom rows from output for BDD landscape images. That label convention is not an inference transform for arbitrary input aspect ratios.
- Upstream demo uses a 640-square nominal input with stride-adjusted automatic padding and restores using an integer inverse ratio. The adapter deliberately uses the training image resolution, exact recorded top/bottom/left/right padding, and an explicit target size for original-frame restoration. This avoids assuming a fixed 12-row crop or an integer inverse scale for portrait and odd-sized images.
- Both heads have channel 0 background and channel 1 positive semantic pixels. The loader thresholds each grayscale annotation at >1 to create binary targets. The adapter removes padding from both full-resolution score maps, bilinearly restores both channels with `align_corners=False`, then argmaxes; no sigmoid or arbitrary threshold is used. `FrameRoadSegmentation` owns separate original-resolution boolean masks. Drivable area is not all road surface, and the lane mask is not a fitted boundary, centerline, or trajectory.
- Deterministic tests exercise wide landscape, tall portrait, square, odd dimensions, asymmetric padding, RGB channel order, padding-only false positives, spatial corner markers, model-output shape, and input immutability. No adapter correctness defect was found in this audit; the new tests strengthen alignment coverage.

## M4 — Sampling, geometry, and regression evidence

- M4 began from a clean M3 commit M3 milestone; M2 and P0/P1 history are preserved. No remote exists and nothing was pushed.
- Both methods operate on the same original-resolution frame, detections, and depth. Box membership is based on integer pixel centers in clipped float `[x1,x2)×[y1,y2)`; mask membership is the instance mask intersected with that box. The shared valid mask means finite positive camera-axis Z. Defaults are at least 3 valid pixels and at least 10% valid fraction. Median is the representative region Z; mean/min/max, population standard deviation, IQR, MAD, counts, fraction and >=99%-of-nominal-80-m near-cap fraction remain diagnostics. A failed threshold is marked unavailable even when diagnostic values exist. No invalid depth is replaced with zero and no per-test-label tuning is used.
- Each method chooses an actual valid pixel by minimum absolute difference to its region median, then minimum squared distance to the centroid of *all region pixels*, then smaller row `v`, then smaller column `u`. This same policy is used for box and mask. The pixel's own Z can differ from median Z. Selected-ray backprojection uses only that actual Z. Missing, empty, sparse, clipped-away, invalid, and no-depth cases have explicit status/reason; overlapping detections are sampled independently.
- The rectified pinhole implementation uses `X=(u-cx)Z/fx`, `Y=(v-cy)Z/fy`, `Z` forward, and separately computes Euclidean radial range. It requires finite positive focal lengths, finite principal point, matching image dimensions, explicit rectification, and calibration provenance. Synthetic backprojection tests pass; real calibrated backprojection remains undemonstrated. A raw `P2` calibration file is rejected rather than dropping its translation terms. The bus photo has no verified intrinsics, so all metric 3D coordinates are unavailable. Surface points, when available, are *estimated visible scene points*, not KITTI object-reference locations.
- Baseline fast suite: 45 passed, 2 skipped. After M4: **59 passed, 3 skipped**. The opt-in real depth, road and fusion checkpoint suite: **3 passed**. Detector CLI regression: six bus-image detections. The CPU fusion CLI produced six detections, six valid box medians and six valid mask medians; JSON and overlay were generated. Its median pairs `(box, mask)` in meters by detector order are: bus `(12.73, 13.01)`, person `(13.06, 9.25)`, person `(10.18, 9.65)`, person `(10.69, 10.23)`, stop sign `(16.52, 16.34)`, person `(9.78, 9.38)`. These are unlabeled predictions, not accuracy scores. Full per-object counts and provenance are in `outputs/bus_fusion.json`.
- At the M4 boundary, remaining limitations were VKITTI synthetic-to-real shift, possible occlusion/background contamination, incomplete or noisy instance masks, sparse small objects, near-80-m saturation, no calibrated monocular uncertainty, no KITTI quantitative evaluation yet, and lack of verified bus calibration. - Source: user-supplied local KITTI object benchmark archives for the labeled **training** partition: `data_object_image_2.zip` (12,569,945,557 bytes), `data_object_label_2.zip` (5,601,213 bytes), `data_object_calib.zip` (26,854,811 bytes), and `devkit_object.zip` (63,794 bytes). Their expected archive structure and 7,481 training IDs were checked. Official downloads may require account registration; none was attempted. All 7,481 training labels and calibrations, then only the frozen 16 pilot and 256 held-out left-color images, were extracted under ignored `datasets/`. Individual selected-image SHA-256 digests, small-archive SHA-256 digests and archive member counts are in `outputs/kitti_m5/dataset_provenance.json`. The large image ZIP itself was not hashed end-to-end, so its publisher authenticity is not independently established. No unofficial mirror or another robotics project's data is used.
- Label parser requires the documented 15 fields and retains object ID (line index), category, truncation, occlusion, alpha, float 2D box, dimensions `(h,w,l)`, camera-frame location `(x,y,z)`, rotation Y, and validity status. Empty files are supported; malformed field counts, bad numerics and invalid boxes fail. `DontCare`, unsupported categories, invalid dimensions and nonpositive reference Z are tracked explicitly. Loader checks selected image/label/calibration IDs and rejects corrupt images. The class policy permits only `car`→`Car` and `person`→`Pedestrian`; Van, Truck, Tram, Misc, Person_sitting, Cyclist, DontCare and unsupported COCO classes are counted without remapping.

Optional `R0_rect` and `Tr_velo_to_cam` matrices are parsed/validated but are **not** used to manufacture a surface reference. The primary proxy compares M4 medians with annotated object-reference forward `location_z`, not Euclidean range or 3D point-localization error. A LiDAR visible-surface diagnostic requires separate approved points, rectification, projection, z-buffering and defensible correspondence, so it remains pending.

## M6 — Association and visualization decisions

- The fixed, untuned default band starts at the exclusive lower box edge, spans the center 60% of box width and max(2 pixels, ceil(15% of box height)) vertically. Integer pixel centers belong to clipped half-open bounds. Minimum visible area is six pixels and 50% of the ideal pixel count; foreground overlap ≥0.50 is the inclusive detection threshold. A box touching the left, right, top or bottom image edge gives `unknown_image_boundary` without claiming true truncation. Explicit annotation hints produce distinct `unknown_truncated` and `unknown_occluded` statuses and remain recorded with the result. A clipped band below the minimum visible fraction gives `unknown_insufficient_coverage`; zero pixels give `unknown_invalid_region`; too few pixels or absent road prediction give `unknown_insufficient_evidence`. Hints are never inferred by YOLO. Fractions remain diagnostic even for an unknown status and are not calibrated probabilities. The drivable mask alone is counted; lane pixels stay semantically distinct.
- Scene objects carry stable detection IDs, class/confidence/box, mask availability, unchanged M4 box/mask statistics and selected samples, optional M4 visible-surface points, road evidence, provenance and warnings. The scene carries policy, model hashes, calibration and visualization statuses. Full-resolution masks and depth arrays are omitted from JSON. M4's nested depth preprocessing is copied and made recursively immutable in `FrameFusionResults`; JSON returns fresh ordinary objects. Synthetic tests verify no upstream mutation and strict non-finite rejection.
- Camera visualization keeps original image alignment and uses separate translucent drivable/lane colors. The metric plot uses M4 actual selected-pixel depth, X right and Z forward in meters, equal scale and visible camera origin. It does not depict a road plane, object footprint, heading or center. A verified rectified pinhole calibration is required; raw KITTI `P2` is incompatible with this simple interface because its translation/reference frame must be handled explicitly. The uncalibrated bus image produces `unavailable_no_intrinsics` and no X–Z file. The synthetic calibrated example has known intrinsics and selected rays at (25,35,10) and (75,35,20), yielding (−5,10) and (+10,20) m in X–Z.
- The independent review reproduced a stale-association case: a scene accepted an all-zero drivable mask with the same frame/model/checkpoint identifiers while retaining positive associations from the original mask. `FrameRoadAssociations` now records deterministic SHA-256 fingerprints for detector-order identities/boxes, the full policy and the actual road prediction. Validation checks all digests and recomputes contact coordinates, ideal/visible/foreground counts, fractions, status and reason using preserved visibility hints; overlay rendering verifies the pairing again. Fingerprints show local source consistency, not checkpoint authenticity or output accuracy. The mask arrays are not duplicated in scene JSON. Tests cover same-count different-position masks, stale masks, altered checkpoint/policy/detections, tampered diagnostics, missing-road pairing and visualization rejection.

Every present mask contributes C-row-major one-byte boolean pixels (0/1) with an eight-byte big-endian length prefix; absent and empty-but-present masks have distinct header states. Scene assembly recomputes the digest from supplied detections and rejects missing or mismatched fingerprints; overlay rendering inherits that check. The independent road-association detector fingerprint deliberately remains box-only. Existing standalone fusion results without the optional field still serialize, but new scene assembly requires verifiable detector-mask provenance. This is local data-consistency evidence, not proof of model authenticity or accuracy. Tests cover same-count mask changes, absence/presence, layout equivalence, metadata/order changes, tampered fingerprints and overlay rejection; M4 medians and calibrated geometry remain unchanged.
